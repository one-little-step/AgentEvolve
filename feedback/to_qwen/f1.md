Repository Context Established
AgentEvolve is an agent-neutral RHO-Parallel-GEPA research framework for evolving adapter-declared agent artifacts such as skills, memory, policies, workflows, and prompts. The active target is a generic evolution core plus a future IBM CUGA SDK adapter. Gaia is retained only as a read-only historical reference.
The required architecture/migration materials and the full historical RHO archive have been reviewed. The project’s central constraints are clear:
- src/agent_evolve/core/ must remain free of CUGA, Gaia, and concrete agent imports.
- CUGA APIs, trace fields, artifact types, checkpoints, and replay semantics must not be guessed; the official SDK/docs need inspection before adapter work.
- Replay is valid only when an adapter explicitly proves checkpoint/state reconstruction support.
- The generic core must not encode Gaia filenames, Markdown semantics, evaluator internals, expected answers, credentials, or labels.
- Every test, smoke run, and migration verification must capture output with 2>&1 | tee terminal_output/....

Important Reality Check
The docs correctly describe several major capabilities as planned or feature-gated. The code contains useful primitives and tests, but does not yet deliver the end-to-end target system. In particular, there is currently:
- No CUGA SDK integration or production adapter.
- No real agent/model rollout runtime or dataset integration.
- No validated checkpoint discovery or counterfactual replay path.
- No actual concurrent worker execution; the current “parallel” orchestrator path executes workers sequentially.
- No orchestrator integration for entropy-driven selection, DPP selection, merge/crossover, replay, or deferred generalization probes.
- Origin-only validation in the active orchestrator flow, rather than complete worked/regression/generalization validation.
- No production analyzer/judge; only deterministic fake components.
High-Priority Flaws Identified
 1. src/agent_evolve/core/pool.py:145-153  
mean_score_per_task() uses the first character of each task ID as its aggregation key. This merges unrelated tasks with the same leading character and invalidates per-task aggregates.
 2. src/agent_evolve/core/editor.py:209-225  
floors_violated() is effectively unfinished: it contains a pass, ignores mechanism-cluster matching, and falls back to a task-wide maximum rather than enforcing the documented protected-floor behavior.
 3. src/agent_evolve/core/orchestrator.py:654-671  
Parallel-path accepted candidates are admitted without score-tensor evidence and without recording edit-memory attempts. This breaks candidate provenance, Pareto evidence, entropy readiness, and retry history for parallel admissions.
 4. src/agent_evolve/core/parallel.py:217-263  
BatchCoordinator.commit_barrier() claims all-or-nothing commits but runs callbacks sequentially without rollback. A later callback failure leaves earlier mutations persisted.
 5. src/agent_evolve/core/memory.py:65-77 and core/editor.py:350-377  
Memory sanitization only rejects prohibited top-level keys. It does not recursively examine nested structures or sensitive strings. The active attempt builder can persist editor write payloads, creating a direct risk of storing expected answers or sensitive evaluator details, which violates AGENTS.md.
 6. src/agent_evolve/core/orchestrator.py:283-297  
The orchestrator applies all returned edits without enforcing that they are in the editor request’s write_set. A malformed or malicious editor could modify artifacts outside the authorized scope.
 7. src/agent_evolve/core/entropy.py:252-307  
The purported DPP selector rewards similarity instead of penalizing it, so it tends toward redundant selections. lambda_div, item diversity weighting, and RNG configuration are unused.
 8. src/agent_evolve/core/orchestrator.py:210-231  
Minimal scoring treats tasks with no expected_substring as automatically successful because the empty string is always present. It also ignores expected_regex.
 9. src/agent_evolve/core/orchestrator.py:469-491  
Failure issue reconstruction discards actual trace/blame evidence and creates a generic synthetic node, causing editors to fall back to the first writable artifact instead of causally attributed artifacts.
10. src/agent_evolve/core/clustering.py:162-171 and core/merge.py  
   Barrier-time reclustering and merge are modelled but not implemented end-to-end. Merge protected-floor enforcement is currently only a readiness check.

Historical Reference
reference/gaia_evolution_core/ and docs/rho_evolution/ are valuable for rationale, schemas, debugging patterns, and migration comparisons, but are intentionally not runtime dependencies. The active implementation should selectively preserve the good conceptual parts while avoiding Gaia-specific assumptions such as hardcoded Markdown artifacts, synthetic comparability, elite-only retention, and LLM-first merge behavior.
The implementation is best understood as a well-tested foundation/prototype, rather than a completed RHO-Parallel-GEPA system.
