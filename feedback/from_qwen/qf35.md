## II. Architectural Strengths of the Plan

### 1. The "No Best-of-N" Rule is Preserved
The plan explicitly states: *"All N candidates are retained in the pool. NEVER prune to best-of-N."* This is the load-bearing insight from the design spec. The plan enforces this at every stage (Task 8 discards only byte-identical/duplicate candidates, Task 9 ranks but retains all, Task 13 commits all survivors).

### 2. Interface A vs. Interface B Separation is Clean
The plan correctly separates:
*   **Interface A** (structured stateless LLM calls): `cuga_rho_comprehender.py`, `cuga_rho_judge.py`. These take an injectable `completion_fn` and are fully testable offline.
*   **Interface B** (CUGA workspace agents): `cuga_rho_diagnoser.py`, `cuga_rho_optimizer.py`, `cuga_preference_judge.py`. These take an injectable `agent_factory` and use the shared `run_workspace_agent` mechanism (Task 6).

### 3. The Shared Workspace Agent Runner (Task 6)
Extracting the multi-turn agent mechanism from `cuga_editor.py` into `cuga_workspace_agent.py` is a crucial refactoring step. It prevents code duplication across the three RHO Interface B components. The plan wisely defers refactoring `cuga_editor.py` itself to avoid risking the working genetic path under deadline — this is a pragmatic technical debt decision.

### 4. Concurrency Invariant Enforcement (Task 10 + Task 14)
The two-level scheduler (`group_workers` × `rollout_workers` with a `global_cap`) is correctly modeled. The invariant `global_cap <= group_workers * rollout_workers` is enforced at validation time (Task 10) and at the CLI preflight stage (Task 14). The credential-independent preflight check is particularly good UX — a misconfigured run should fail before attempting to contact a model endpoint.

### 5. GT Contamination Safety (Task 9 + Task 12)
The plan correctly handles the GAIA test splits' placeholder regexes (`(?i)\?`) by filtering them out in `cuga_preference_judge.py` (Task 9). The post-hoc contamination detector (Task 12) provides an additional safety net for the explicit `AGENTS.md` override that allows GT to reach the preference judge.

## III. Critical Areas Requiring Careful Attention During Execution

### 1. Task 11: Entropy Skip Tier Removal
**Risk:** Removing the `"skip"` tier from `EntropyTracker.classify` is a behavioral change that will affect every caller of that method.
**Mitigation:** The plan correctly identifies that `issues.raw_issue_quality` has a branch for `"skip"` that will become dead code. Ensure that all existing tests in `test_entropy.py` and `test_issues.py` are updated to reflect the new two-tier contract (`"frontier_exploration"` or `"recombination_target"` only). Do not restore the skip tier if tests fail — update the assertions instead.

### 2. Task 11: `propose_edits` Arity Change
**Risk:** Changing `propose_edits` to return 4 values instead of 3 is a breaking change for all callers.
**Mitigation:** The plan includes a `grep` step to find and update all callers. **Do not skip this step.** Common callers that may break:
*   `run_attempt` in `orchestrator.py` (updated in Step 5)
*   `tests/test_phase_6_orchestrator.py`
*   `tests/test_orchestrator_editor_wiring.py` (from Phase 8 Task 11)
*   `examples/run_phase_6_b1.py` (if it calls `propose_edits` directly)

Run the full suite immediately after Step 5 to catch any missed callers.

### 3. Task 6: Technical Debt Acknowledgment
**Risk:** By not refactoring `cuga_editor.py` to use the new `run_workspace_agent` helper, the codebase will have two implementations of the workspace agent mechanism.
**Mitigation:** This is acceptable for now, but should be tracked as technical debt. Once the RHO stage is proven stable, a follow-up task should refactor `cuga_editor.py` to use `run_workspace_agent` for consistency.

### 4. Task 15: Live Wiring Deferral
**Risk:** The plan explicitly defers live pipeline wiring (`pipeline.py` RHO stack construction) to a future plan.
**Mitigation:** This is the correct strategic call. Tasks 1-14 build and unit-test every component, but connecting them to `build_live_stack` requires a fresh trace corpus (the existing 42-task traces are stale-format). The plan correctly identifies this dependency in the "Not in this plan" section.
