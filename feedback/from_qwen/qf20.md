## II. Critical Bug: Must Fix Before Phase 5

### Bug in `issues.py` Line ~55

```python
@dataclass(frozen=True, slots=True)
class Issue:
    ...
    writable_artifact_ids: tuple[str, ...]
    ...
    def __post_init__(self) -> None:
        ...
        object.__setattr__(self, "writable_artifact_ids", tuple(self.writable_artifacts))
        #                                                              ^^^^^^^^^^^^^^^^
        #                                                              BUG: should be writable_artifact_ids
```

`self.writable_artifacts` does not exist as an attribute. This will raise `AttributeError` when any `Issue` is constructed via the dataclass constructor (which happens in tests and in `build_issue()`).

**Fix:**
```python
object.__setattr__(self, "writable_artifact_ids", tuple(self.writable_artifact_ids))
```

Or simply remove this line entirely since the dataclass already stores the field as a tuple from construction.

**Impact:** This bug will cause test failures whenever `Issue` is instantiated. If tests are currently passing (470 tests), it means either:
1. The tests don't actually construct `Issue` via the dataclass constructor, or
2. The `__post_init__` path is not being exercised

Either way, this is a latent crash that will surface when the orchestrator or adapter constructs issues in production.

## III. Deferred Gaps (Phase 5 Must-Fix)

These were triaged by the final review and correctly deferred. Here is the precise scope of each:

### 1. Champion Manifest Report

**Current state:** `select_champion()` returns a `PoolEntry` with the aggregate computed internally but not exposed.

**Phase 5 requirement:** Return a structured `ChampionReport` with:
```python
@dataclass(frozen=True)
class ChampionReport:
    candidate_id: str
    outcome: float
    coverage: float
    stability: float
    regression_risk: float
    aggregate: float
    alpha: float
    beta: float
    gamma: float
    delta: float
    tie_breaker: str
```

**Why it matters:** The architecture requires "The manifest must expose every component and tie-breaker." Without this, ablation experiments cannot report which component drove the champion selection.

### 2. Min-Coverage Disqualification

**Current state:** `select_champion()` does not check that a candidate has sufficient evaluation coverage before ranking it. A candidate with 1 evaluated cell and perfect score could beat a candidate with 10 evaluated cells and slightly lower score.

**Phase 5 requirement:** Add a `min_coverage_fraction` parameter (e.g., 0.3) to `select_champion()`. Disqualify candidates whose `ProcessCoverage < min_coverage_fraction` before computing aggregate.

**Why it matters:** Without this, the champion selection can be dominated by specialists with narrow evidence, violating the architecture's intent that "The champion is selected only after budget exhaustion from the persistent pool" with "transparent aggregate over outcome quality, process coverage, rollout stability, weighted regression risk, comparison coverage."

### 3. Incremental Entropy Stats + Frontier Weight Wiring

**Current state:** `EntropyTracker.classify()` uses `recombination_score_threshold` and `frontier_weight`, but the wiring to `issues.py` is incomplete:
- `issues.py` uses `issue.entropy` as a raw input to `raw_issue_quality()`, but does not distinguish `recombination_target` from `frontier_exploration` tiers.
- The `frontier_weight=0.30` is defined in config but not applied to the quality calculation.

**Phase 5 requirement:** In `issues.py`, when computing `raw_issue_quality()`, multiply the entropy component by `frontier_weight` when the entropy tier is `frontier_exploration`:
```python
def raw_issue_quality(issue, *, normalized_entropy, entropy_tier, frontier_weight, weights):
    entropy_signal = normalized_entropy
    if entropy_tier == "frontier_exploration":
        entropy_signal *= frontier_weight
    elif entropy_tier == "skip":
        entropy_signal = 0.0
    ...
```

**Why it matters:** The architecture specifies that "frontier cells below the recombination threshold retain the configured frontier weight." Without this wiring, frontier cells contribute full entropy weight, defeating the two-tier classification.

## IV. Minor Inconsistency

### `entropy.py` References Undefined Methods

The extracted code for `entropy.py` references `self._meets_evidence_floor(cell)` and `self._comparable_scores(cell)` which are not shown in the extraction. These methods must exist in the full file. If they don't, the `entropy()` and `classify()` methods will raise `AttributeError`.

**Verification needed:** Confirm these methods exist in the full `entropy.py` file. If they don't, they need to be added:
```python
def _meets_evidence_floor(self, cell: _Cell) -> bool:
    comp = {c for c in cell.comparable if c in cell.scores}
    if len(comp) < self.min_comparable_candidates:
        return False
    return all(len(cell.scores[c]) >= self.min_rollouts_per_candidate for c in comp)

def _comparable_scores(self, cell: _Cell) -> list[float]:
    comp = {c for c in cell.comparable if c in cell.scores}
    return [s for c in comp for s in cell.scores[c]]
```
