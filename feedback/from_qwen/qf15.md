# Resolving the Adapter Bootstrap Problem

Your question identifies a real architectural tension, but the resolution is already embedded in the design. Let me trace the dependency chain precisely.

## The Apparent Circularity

```
Phases 3-6 (evidence, selection, editing, merge, orchestration)
    → need an adapter to run rollouts and collect traces
        → but the CUGA adapter is Phase 8
            → which needs the CUGA wrapper (Phase 7)
                → which needs Phases 1-6 to pass first
                    → CIRCULAR?
```

## Why It Is NOT Circular

The key architectural decision that breaks this cycle is the **adapter-neutral core**. The core phases do not need the CUGA adapter. They need the `EvolutionAdapter` **protocol** (already defined in `contracts.py`), which can be satisfied by a **fake adapter**.

```
Phase 1-2: contracts, config, storage
    → No adapter needed at all
    → Pure data contracts, profile resolution, SQLite transactions

Phase 3-6: evidence, selection, editing, merge, parallel, orchestration
    → Need the EvolutionAdapter PROTOCOL (already in contracts.py)
    → Tested with FakeAdapter / InMemoryRuntime (already in examples/)
    → Do NOT need CUGA, CUGA wrapper, or CUGA tracing

Phase 7: CUGA wrapper (including tracing)
    → Needs Phases 1-6 to pass
    → Needs CUGA SDK installed
    → Produces rich CausalTrace

Phase 8: CUGA adapter
    → Needs Phase 7 wrapper
    → Needs SDK verification matrix
    → Replaces FakeAdapter with real CUGA integration
```

The dependency is **linear**, not circular. Phases 3-6 are tested against a fake adapter. The CUGA adapter arrives later and satisfies the same protocol.

## What Phases 3-6 Actually Need From an Adapter

Looking at the `EvolutionAdapter` protocol in `contracts.py`:

```python
class EvolutionAdapter(Protocol):
    adapter_name: str
    def artifact_inventory(self, version: str) -> Sequence[ArtifactDescriptor]: ...
    def read_artifacts(self, version: str, artifact_ids: Sequence[str]) -> Mapping[str, str]: ...
    def materialize_candidate(self, parent_version: str, attempt_id: str) -> CandidateWorkspace: ...
    def apply_structured_edits(self, workspace: CandidateWorkspace, edits: Sequence[ArtifactEdit]) -> Mapping[str, str]: ...
    def run_full_rollout(self, workspace: CandidateWorkspace, task: EvolutionTask, rollout_id: str) -> object: ...
    def capture_trace(self, rollout_result: object) -> ExecutionTrace: ...
    def supports_counterfactual_replay(self) -> bool: ...
    def discover_checkpoints(self, trace: ExecutionTrace) -> Sequence[CheckpointDescriptor]: ...
    def replay_from_checkpoint(self, checkpoint: CheckpointDescriptor, workspace: CandidateWorkspace, task: EvolutionTask, rollout_id: str) -> object: ...
```

Every one of these can be implemented with a deterministic fake:

| Method | Fake Implementation |
|---|---|
| `artifact_inventory()` | Return a hardcoded list of `ArtifactDescriptor` |
| `read_artifacts()` | Return hardcoded strings from a dict |
| `materialize_candidate()` | Create a temp directory with copied files |
| `apply_structured_edits()` | Apply string operations to files in the temp dir |
| `run_full_rollout()` | Return a deterministic result based on task input |
| `capture_trace()` | Return a synthetic `ExecutionTrace` with fake events |
| `supports_counterfactual_replay()` | Return `False` |
| `discover_checkpoints()` | Return empty tuple |
| `replay_from_checkpoint()` | Raise `NotImplementedError` |

This is exactly what the existing `InMemoryRuntime` and `FakeAdapter` in `examples/` already do. The 202 passing tests in the current suite are built on this foundation.

## What the Tracing Plan Actually Adds

The tracing plan (`2026-08-12-cuga-causal-tracing.md`) is **Phase 7**. It adds rich causal trace collection to the CUGA wrapper. But the core phases do not depend on this rich trace. Here is the distinction:

| Trace Type | Produced By | Consumed By | Required For |
|---|---|---|---|
| `ExecutionTrace` (minimal) | Any adapter (including fake) | Core phases 3-6 | Basic rollout evidence, score tensor |
| `CausalTrace` (rich) | CUGA wrapper (Phase 7) | Analyzer/judge (Phase 3) in production | Causal blame graphs, counterfactual analysis |

The core phases work with `ExecutionTrace`. The rich `CausalTrace` is an enhancement that improves the quality of causal analysis when running with the real CUGA adapter, but it is not a prerequisite for building or testing the core.

```
Step 1: Phase 1 (contracts, errors)
    Test with: pure unit tests, no adapter needed
    
Step 2: Phase 2 (config, storage)
    Test with: pure unit tests, no adapter needed
    
Step 3: Phase 3 (pool, analysis, blame, clustering)
    Test with: FakeAdapter + InMemoryRuntime
    The fake adapter provides deterministic ExecutionTrace objects
    The analyzer/judge consumes these traces and produces verdicts
    
Step 4: Phase 4 (entropy, issues, memory, editor, evaluation)
    Test with: FakeAdapter + InMemoryRuntime
    The editor proposes edits, the evaluator runs focused validation
    
Step 5: Phase 5 (merge, parallel)

Step 6: Phase 6 (orchestrator)

```

## What the Fake Adapter Must Provide for Each Phase

### Phase 3 (Evidence and Diagnosis)
The fake adapter must produce `ExecutionTrace` objects with enough structure for the analyzer/judge to work:

```python
class FakeAdapter:
    def run_full_rollout(self, workspace, task, rollout_id):
        # Deterministic result based on task.task_id
        return {"status": "success", "output": f"answer-{task.task_id}"}
    
    def capture_trace(self, result):
        return ExecutionTrace(
            trace_id=f"trace-{uuid4()}",
            candidate_id="candidate-1",
            task_id="task-1",
            events=(
                TraceEvent(event_id="e1", kind="llm_call", actor_id="agent", parent_event_id=None, payload={"prompt": "..."}),
                TraceEvent(event_id="e2", kind="tool_call", actor_id="agent", parent_event_id="e1", payload={"tool": "search"}),
            ),
            final_output=result["output"],
            status=result["status"],
            checkpoint_ids=(),
        )
```

### Phase 4 (Selection and Editing)
The fake adapter must support artifact read/write:

```python
class FakeAdapter:
    def __init__(self):
        self._artifacts = {
            "wisdom/reAct.md": "# ReAct Strategy\n...",
            "skills/retrieval-recovery.md": "# Recovery\n...",
        }
    
    def read_artifacts(self, version, artifact_ids):
        return {aid: self._artifacts[aid] for aid in artifact_ids}
    
    def apply_structured_edits(self, workspace, edits):
        for edit in edits:
            if edit.operation == "append_section":
                self._artifacts[edit.artifact_id] += f"\n## {edit.payload['heading']}\n{edit.payload['content']}"
        return dict(self._artifacts)
```

### Phase 5 (Merge and Parallel)
The fake adapter must support versioned artifact hashes:

```python
class FakeAdapter:
    def artifact_inventory(self, version):
        return (
            ArtifactDescriptor(
                artifact_id="wisdom/reAct.md",
                kind="wisdom",
                format="markdown",
                version_hash=f"sha256:{hashlib.sha256(self._artifacts['wisdom/reAct.md'].encode()).hexdigest()}",
                readable=True,
                writable=True,
                merge_strategy="text-by-ancestor",
                phase_bindings=("reAct",),
            ),
        )
```

### Phase 6 (Orchestration)
The fake adapter ties everything together. The orchestrator calls the full lifecycle: select issue → read artifacts → propose edit → apply edit → validate → commit.

## The Tracing Plan's Position Is Correct

The tracing plan is correctly placed as Phase 7 because:

1. **It requires Phases 1-6 to pass.** The tracing plan's Task 0 explicitly verifies the phase gate before any production work.

2. **It requires the CUGA SDK.** The tracing plan collects traces from CUGA's `agent.invoke()`, `agent.stream()`, and `agent.graph`. These are CUGA-specific APIs that don't exist in the fake adapter.

3. **It enhances, not replaces, the core.** The tracing plan adds `CausalTrace` persistence alongside the existing `ExecutionTrace`. The core phases continue to work with `ExecutionTrace`. The rich `CausalTrace` is consumed by the analyzer/judge for better causal analysis, but the core doesn't break without it.

4. **It does not block Phases 3-6.** Phases 3-6 are tested with the fake adapter. The tracing plan is an independent increment that adds CUGA-specific trace collection.

### Then: Build Phases 3-6 with the Fake Adapter

## Summary

| Question | Answer |
|---|---|
| Can Phases 3-6 proceed without the CUGA adapter? | **Yes.** They use the `EvolutionAdapter` protocol with a fake adapter. |
| Does the tracing plan block Phases 3-6? | **No.** Tracing is Phase 7, which comes after Phases 1-6. |
| Can the CUGA adapter be built before Phases 3-6? | **No.** The phase gate requires Phases 1-6 to pass first. |
| Is the dependency chain circular? | **No.** It is linear: Phases 1-6 (fake adapter) → Phase 7 (CUGA wrapper) → Phase 8 (CUGA adapter). |
| What breaks the apparent circularity? | **The adapter-neutral core design.** The `EvolutionAdapter` protocol decouples core logic from any specific agent runtime. |

The architecture is designed to be bootstrapped incrementally. You do not need CUGA to build and test the evolutionary core. You need CUGA only when you reach Phases 7-8. Until then, the fake adapter provides deterministic, reproducible test evidence for every core phase.
